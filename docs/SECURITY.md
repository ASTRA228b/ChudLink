# Security and trust model

USB mode is opt-in and requires the user to enable Android USB debugging and authorize their own PC. Authorized ADB reverses the phone's TCP 47831 to the host's loopback TLS listener. A random 256-bit, single-use, two-minute bootstrap code is accepted only from loopback; it does not bypass the phone's first-time fingerprint confirmation or explicit PC approval. Normal Wi-Fi codes are independent. Subsequent USB connections retain the existing certificate pin and device credential. Unrecognized intent offers cannot replace an existing host without confirmation. USB never enables wireless ADB or installs an APK automatically. Local processes on an already authorized or compromised PC remain within the trust boundary.

The desktop starts the local host automatically unless disabled in Settings, and binds loopback alongside the selected private interface for USB. The user-initiated Wi-Fi setup button requests Windows elevation and creates only application/port-specific, Private-profile, LocalSubnet firewall exceptions. It never disables the firewall or changes a Public network's profile. No firewall rule is required for USB.

The local network is not trusted for device identity. HTTPS/WSS uses a persistent per-host self-signed certificate pinned by full SHA-256 on the phone. Pair only after comparing the fingerprint against the PC. Discovery cannot prove identity. No certificate trust store is changed, and the client never accepts an arbitrary certificate. The app operates offline after installation.

Pairing uses a single-use two-minute numeric code, explicit approval on the PC and an unpredictable poll ticket. The poll ticket and device credentials travel only over pinned TLS and in headers, not query strings. Device tokens are 256-bit random values; only their hashes are persisted on the host. Revocation aborts the active socket and rejects reconnection. The private certificate remains in the current user's application-data folder; current-user processes can access it. This product does not protect against a compromised Windows user account.

Kestrel binds a selected private/loopback IPv4 address. It rejects peers outside private IPv4 ranges. HTTP requests are limited per remote IP, WebSocket messages per connection, and payload sizes/depth/widget counts are bounded. Device actions are resolved from host dashboard event bindings, never supplied executable commands. Shell/launch/build actions require a locally configured fixed executable and arguments plus a per-device permission. No remote shell or remote management endpoint exists.

**Arbitrary C# extensions are executable code, not data.** Separate workers, IPC permission checks and Job Object limits do not stop a malicious assembly from reading user files, opening network connections or invoking Windows APIs under the current account. Do not enable third-party code you cannot trust. Installation only extracts a reviewed package; no code automatically runs after installation or on startup. Developer Studio requires an explicit local trust choice before Run. For actual hostile code, use a separate OS account, VM or a separately designed isolation boundary; ChudLink does not claim such isolation.

Worker Job Objects enforce 256 MB process memory, 20% CPU and a single active process, with kill-on-job-close. The host applies a four-hour lifetime and bounded protocol output. Extension commands require the matching manifest permission, but that governs **ChudLink IPC only**, not arbitrary .NET or Windows behavior. Extension settings may include private configuration; do not export it with public packages.

Package installation checks SDK version, namespaced IDs, known permissions, assembly basename, zip traversal, total uncompressed size (32 MB) and file count (256). Packages are not cryptographically signed or authenticated in this alpha. Update is an explicit disable/uninstall/reinstall flow; there is no automatic updater.

Keep `%LOCALAPPDATA%/ChudAI/ChudLink` out of public releases. It contains certificate/private data. The repository ignores local certificates, developer keys, build output and *.local.json. Android app backup is disabled, credentials are stored in private app preferences and normal operation requests only Internet/network-state access. Sensor sharing is opt-in at both ends.
